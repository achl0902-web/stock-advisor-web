# 모바일 렌더링 회귀검사와 수동 검수 기준

## 배경

2026년 11월 27일 사용자가 제공한 iPhone 화면에서 날짜 입력칸 가로 겹침과 하단 메뉴/콘텐츠 가림 정황이 발견됐다. 종전 `test/mobile-layout.test.mjs`는 CSS 선언의 존재를 정규식으로 확인해 실제 레이아웃 결과를 판정하지 못했다. 기존 정적 검사는 유지하되, PR마다 실제 브라우저에서 화면 요소의 위치·크기를 측정한다.

## 자동 검사

- 명령: `npm run check:browser` (먼저 `npm ci`와 `npx playwright install chromium`).
- 데이터: `preview-demo.html#/assets`의 가상 계좌·평가액. 비공개 GitHub 토큰이나 실제 계좌 데이터는 사용하지 않는다.
- 폭: 320·375·390·430 CSS px, 터치 가능한 Chromium, 높이 844px.
- 조건: 기간 슬라이더 기본 펼침, 시작·종료일 필드 비겹침/카드 경계, 날짜 값 비잘림, 화면의 의도치 않은 가로 넘침, 조작부 44px 목표, 최하단 콘텐츠를 하단 도크 위에서 확인 가능.
- 상호작용: 퇴직연금 토글로 자산 카드 수치 변경, 1주 기간 프리셋에 따라 표시 날짜 변경, 두 동작 후 기간 슬라이더 계속 펼침, 중복 `선택 계좌 구성` 카드 부재.
- 실패 시 `browser-artifacts/assets-<폭>.png`를 생성하고 CI에서 아티팩트로 보관한다.

이 검사는 Playwright가 내려받은 Chromium에서 동작하며, **iOS Safari/WebKit·VoiceOver 실기기 검증을 대체하지 않는다.** 브라우저 설치·실행에 실패하면 검사는 실패로 남겨야 하며 정적 검사 통과로 대체해선 안 된다.

## 병합 후 수동 검수

1. 실제 배포 커밋 및 캐시 갱신 확인.
2. iPhone Safari에서 320/375/390px 상당 폭 및 실제 기기 세로·가로 모드의 날짜 입력·그래프·도넛·하단 메뉴를 확인.
3. Safari 주소창 펼침/접힘과 화면 최하단 스크롤 시 조작 불가 또는 가림이 없는지 확인.
4. VoiceOver로 계좌 토글→기간 조정(손잡이·±7일)→수익률→도넛 대체 목록을 순서대로 탐색.
5. 실제 계좌의 기간·계좌 선택 및 종목별 시세 기준일을 원자료와 대조. **수집 시각이 새롭다는 이유만으로 종목 종가를 최신이라고 판정하지 않는다.**
6. 각 실패는 기기/브라우저 버전, 배포 SHA, 재현 단계, 스크린샷, 관련 검수표 항목으로 기록.

## 완료 판정

자동 테스트 성공은 **브라우저 회귀 통과**다. 실제 iPhone Safari·VoiceOver·실계좌 검증이 끝나기 전에는 모바일 UX/접근성 전체를 완료로 표시하지 않는다. 단계별 상태는 [모바일 UX 및 WCAG 2.2 검수 Page](https://chatgpt.com/space/page_a552832e685c8191bd65f87d9fe93616)에 반영한다.
