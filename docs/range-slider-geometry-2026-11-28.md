# 기간 슬라이더 좌표 불일치 재발 방지 (2026-11-28)

## 사용자 녹화에서 재현된 오류

- 화면의 시작일·종료일이 모두 `2025.08.23`인데 손잡이가 트랙의 양 끝에 나타남.
- 시작일을 고정하고 종료일을 바꾸면 시작 손잡이의 위치도 바뀜.
- 노란 선택 구간과 두 네이티브 손잡이의 위치가 일치하지 않음.

## 원인

`assets/view-assets.js`에서 시작 슬라이더의 `max`를 종료 인덱스 `b`로, 종료 슬라이더의 `min`을 시작 인덱스 `a`로 재설정했음. 브라우저는 HTML `range`의 전체 표시 길이를 각각 `[0,b]`, `[a,N-1]`로 재계산하지만 노란 선택 구간은 `[0,N-1]`로 계산했음. 특히 `a=b`이면 시작 손잡이는 오른쪽, 종료 손잡이는 왼쪽에 나타날 수 있음.

## 수정 불변조건

1. 두 네이티브 `input[type=range]` 모두 `min=0`, `max=N-1`을 유지한다.
2. 선택 구간 CSS 변수 `--a`, `--b`도 같은 `index/(N-1)`로만 계산한다 (`rangePercent`).
3. 시작/종료 교차 제한은 사용자가 입력했을 때만 JavaScript에서 처리하고, `min/max`를 동적으로 바꾸지 않는다.
4. 시작 날짜가 고정되면 종료 날짜를 변경해도 시작 손잡이의 중심 좌표는 변하지 않는다.
5. 두 날짜가 같으면 두 손잡이의 중심과 선택 구간의 양끝이 일치한다.

## 검증

- `npm run check`: 공통 좌표 변환과 기존 날짜·성과 회귀.
- `npm run check:browser`: 450일 가상 기록의 시작일 고정/종료일 변경, 동일 날짜, 전체·1개월 기간, 네이티브 손잡이 직접 드래그를 Chromium과 WebKit에서 확인.
- 모바일 320/375/390/430px 레이아웃, 기본 펼침, 44px 터치 영역, 키보드·날짜 직접 입력 검사는 기존 게이트 유지.
- iPhone Safari 실기기에서의 손가락 드래그·스크롤 충돌은 자동 WebKit 검사와 별도로 확인해야 함.

## 아래로 스크롤할 때 기간 조정

- 원래 기간 패널이 상단 헤더 밖으로 완전히 올라가면 하나의 `range-portable` DOM을 고정 바(`range-float`)로 옮긴다. 네이티브 슬라이더를 복제하지 않는다.
- 원래 자리(`range-portable-slot`)의 높이는 고정 바 전환 직전에 측정해 유지하여 레이아웃·스크롤 점프를 피한다.
- 고정 바에서 시작일·종료일 손잡이와 날짜 선택 버튼을 그대로 사용할 수 있다. 프리셋·정밀 조정은 원래 기간 패널에서 제공한다.
- 기간 패널로 스크롤해 돌아오면 같은 DOM을 원래 자리로 이동한다. 기간 상세가 접히면 고정 바는 표시하지 않는다.
- 320/390/430px Chromium/WebKit 회귀: 스크롤 전/후 손잡이 DOM 1개, 상단 헤더 비겹침, 가로 넘침 없음, 고정 상태에서 기간 변경, 스크롤 복귀 시 손잡이·선택 상태 보존.
