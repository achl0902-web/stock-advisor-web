# 4단계 모바일 UX·접근성 개선 및 검수 — 2026-11-28

## 사용자 경험의 우선순위

- 자산 화면을 중심으로 유지한다. 주 계좌·바이오 기본 토글, 기간 슬라이더 기본 펼침, 손익·수익률·추이 연동, 보유종목 도넛을 변경하지 않는다.
- 기간 조작의 즐거움을 유지하면서, 한 화면 폭에 1년 이상 날짜가 들어갈 때 발생하는 하루 단위 선택의 한계를 보완한다.
- 중복 계좌 구성 요약·불필요한 DC/코인 상세 화면은 복구하지 않는다.

| 4-A 손잡이 선택 | 시작/종료 손잡이가 가까우면 뒤에 쌓인 손잡이가 터치되지 않음 | 본문·고정 기간바 모두에 **시작/종료 조정 선택** 제공, 선택한 native range를 위에 배치 | 두 날짜가 같아도 원하는 손잡이만 선택·이동 |

| 4-B 날짜 입력·고정 UI | iOS native 날짜 선택기는 `focus()` 없이 열릴 수 있어 포커스 이벤트만으로 감지가 불충분 | 포커스뿐 아니라 날짜 입력의 pointer/click도 감지해 두 고정 UI를 감추고 종료·화면 다른 곳 터치 시 복구, 스크롤 여백 확보 | 날짜 선택 중 겹침·초점 가림 없음 |
| 4-C 차트 접근성 | 화면 읽기에서 그래프 출력의 금액 종류와 완전한 날짜 의미가 불명확 | 날짜별 읽기 결과에 전체 ISO 날짜 라벨과 평가액·투자원금 이름 제공 | 보조 버튼/키보드로 날짜별 수치 확인 |
| 4-C 경고 정보 | 지연 시세 상세가 기본으로 펼쳐져 자산 탐색에 방해 | 지연 사실은 표시하되 종목별 내역은 펼쳐서 확인, 상세 글자 14px | 중요한 지연 상태를 숨기지 않고 화면 밀도 완화 |
| 4-D 브라우저 | Chromium 모바일 크기 시험만 존재 | 동일한 화면·상호작용 회귀를 Chromium 및 WebKit에서 실행 | Safari와 구현 엔진이 유사한 WebKit 회귀 추가 |

## 자동 검증과 여전히 필요한 실기기 검증

자동 CI: `npm run check`, `npm run check:browser`, `PLAYWRIGHT_BROWSER=webkit npm run check:browser`.

- 320/375/390/430 CSS px: 가로 넘침, 날짜 입력 겹침, 조작 요소 44px, 하단 콘텐츠 가림, 슬라이더 열린 상태
- 시작·종료 손잡이 겹침, 1일 미세 조정, 트랙 탭, 날짜 입력 중 도크 감추기/복원
- 키보드 손잡이 조작, 테마별 문자 대비(4.5:1), 계좌 토글·기간 변경에 따른 수익률/금액 갱신
- WebKit은 **iPhone Safari와 유사한 렌더링 엔진의 자동 검증**이다. 실제 iOS의 VoiceOver, 네이티브 달력 선택기, 동적 글자 크기, 주소창 애니메이션까지 입증하지는 않는다.

미검증(실제 iPhone Safari/VoiceOver 점검 필요):

1. 겹친 손잡이 직접 터치와 1일 미세 조정, 한 손으로 세로 스크롤과 가로 탐색 전환
2. 날짜 선택기의 열기·확인·취소 이후 포커스와 하단 도크 복원
3. Safari 주소창 축소·확장, 가로 회전, 홈 화면 추가(PWA), 텍스트 200% 확대
4. VoiceOver로 계좌 토글 → 시작일/종료일 → 차트 탐색 → 보유목록을 읽고 조작
5. 실제 계좌 데이터의 휴장일·수집 지연·일부 종목 누락 상태에서 경고의 명확성

**완료 판정:** 자동 회귀가 모두 성공하고, 위 iPhone 실기기 5개 항목을 별도로 확인한 뒤 종합 완료로 표기한다. 자동 검사만으로 WCAG 2.2 전체 적합을 선언하지 않는다.
