# P4 기록 화면 탐색·모바일 접근성 — 2026-11-27

## 발견한 문제

- 판단 기록이 늘면 계좌 필터와 날짜별 목록만으로 과거 종목을 찾기 어렵다. 모든 기록을 초기에 불러오는 방식은 기존의 빠른 화면 진입 목표와 충돌한다.
- 모바일에서 검색할 때 목록 전체를 다시 그리면 입력 포커스와 키보드가 사라질 수 있다.
- 좁은 화면의 판단·성적 행은 표식, 종목명, 수치가 가로로 경쟁해 말줄임이 발생한다.
- 판단 상세를 빠르게 넘기면 먼저 열었던 리포트가 늦게 도착해 **나중에 연 판단의 화면에 잘못 삽입될 가능성**이 있었다. 같은 `#report` ID를 새 문서에서 다시 조회하기 때문이다.

## 조치

1. **불러온 판단 내 검색:** 종목명·티커·계좌·판단 종류·날짜(YYYY-MM-DD, MM/DD)를 입력 즉시 필터링한다. 기존 계좌 칩과 함께 적용하고, 검색 범위/결과 수를 명시한다. 데이터 다운로드와 점수 산식을 바꾸지 않는다.
2. **입력 포커스 유지:** 검색 중에는 목록 결과 영역만 교체해 모바일 키보드가 닫히지 않게 한다. 44px 입력과 테마 공통 포커스 윤곽, 결과 수의 `aria-live` 안내를 제공한다.
3. **작은 화면 수치 보존:** 390px 이하에서는 판단·성적 목록의 주요 숫자를 종목명 아래 줄로 내려 표시한다. 키보드 포커스 윤곽도 추가한다.
4. **오래된 비동기 결과 폐기:** 상세 렌더링 시작 시 DOM 컨테이너를 보관하고, 응답 뒤 그 컨테이너의 연결 및 현재 경로를 확인한다. 그 사이 다른 판단을 열었다면 이전 응답을 폐기한다.

## 보존 및 한계

- 기존의 20건 우선 로딩과 추가 50건씩 로딩, 성적표와 판단의 계산식, 가족 보기의 기록 접근 제한은 변경하지 않는다.
- 검색은 현재 불러온 부분 집합에 한한다. 원격 전체 저장소 검색처럼 오인하지 않도록 범위를 표시한다.
- 자동 검증: DOM에서 검색·계좌 필터·날짜·포커스 유지, 두 상세 화면의 응답 순서 역전, 반응형 CSS 검증. `npm run check`로 전체 회귀 테스트 수행.
- **실기기 미검증:** iPhone Safari 320·375·390px 실측, VoiceOver의 결과 수 안내, 시스템 글꼴 확대는 추가 확인해야 한다.
