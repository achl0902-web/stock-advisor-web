# P2 모바일 조작·접근성 개선 — 2026-11-27

## 문제와 기준

- 자산 추이는 오래된 이력이 한 화면의 좁은 가로축에 모여, 손가락만으로 특정 날짜를 고르기 어렵다.
- 그래프에 뜨는 값 표시가 손가락이나 위쪽 정보와 겹칠 수 있다. 차트 터치 외에도 동일 데이터를 읽는 수단이 있어야 한다.
- 일부 상단 아이콘, 필터 칩, 보조 링크, 펼침 버튼은 기존 44px 조작 목표보다 작았다.
- 320px에서 긴 금액/계좌 행과 상단 도구가 넘칠 위험이 있다.

## 구현 이유와 변경

1. **차트 날짜 접근 경로 이중화.** 차트를 누르거나 드래그해 날짜를 가리키는 동작은 유지한다. 그래프 바로 아래에 **이전 / 선택 날짜·평가액·투자원금 / 다음** 조작 행을 둔다. 44px 이상의 버튼으로 기록이 있는 날을 하나씩 이동할 수 있다. 그래프 포커스에서 좌우·Home·End 키로도 이동한다. 빈 기록은 건너뛴다.
2. **조작과 결과 표시 분리.** 터치 화면에서는 커서 위에 떠 있는 그래프 팝업을 숨기고 아래 결과 행을 활용한다. 아래 결과 행은 날짜·평가액·원금을 `aria-live="polite"`로 갱신한다. 그래프 자체의 정보용 그림 설명과 보유종목 도넛/목록은 유지한다.
3. **정밀 기간 탐색의 이해 가능성.** 원래의 2손잡이 슬라이더와 기본 펼침, 빠른 기간 프리셋, 보조 날짜 직접 입력·±7일 조작은 모두 유지한다. `aria-valuetext`에 실제 시작/끝 날짜를 제공해 스크린리더가 수치 인덱스 대신 날짜로 읽는다.
4. **터치 목표의 크기.** 상단 아이콘·브랜드 링크, 필터 칩, 상세 설명 펼침, 일부 보조 링크를 44px 이상으로 늘린다. 관심종목의 설명 펼침과 차트 날짜 이동도 같은 목표를 적용한다.
5. **화면 폭과 도크.** 320px에서는 상단의 중복 갱신 시각을 감추고(본문 시세 상태는 유지), 투자손익과 수익률은 한 열로 내려 긴 금액 넘침을 막는다. 390px 이하에서는 보유종목 행과 숫자 타일을 줄바꿈 가능하게 한다. 기존 하단 고정 메뉴와 iOS safe area 여백은 그대로 유지한다.

## 보존한 동작

- 주 계좌·바이오 기본 토글, 다중/단일 자산 조합, 보유종목 도넛, 슬라이더 기본 펼침.
- 실시간 평가액과 과거 기간 손익 계산, 원/$ 변경, 가족 보기와 차트 캐시.
- 하단 메뉴는 본문과 분리한 도크로 유지한다.

## 검증과 남은 범위

- `npm run check`: 차트 빌드, 모든 JS 구문 검사, DOM 및 반응형 CSS 회귀 테스트.
- 새 테스트: 이전/다음 버튼, 빈 기록 건너뜀, 원금 표시, 키보드 Home/End/좌우, 포인터 접근, 날짜 `aria-valuetext`.
- 자동 CSS 점검: 320/375/390px 대응 규칙, 44px 버튼, iOS safe area 보존.
- **한계:** 실제 iPhone Safari 손가락 편의성, 시스템 글꼴 확대 및 VoiceOver 안내는 실기기 검증이 필요하다. CSS/DOM 검사를 실기기 검증 완료로 표현하지 않는다.

## 기준

- WCAG 2.2 SC 2.5.8은 예외 조건을 포함해 일반적으로 24×24 CSS px를 최소 목표로 본다. 중요 조작은 더 높은 44×44 CSS px를 목표로 구현했다(SC 2.5.5 참조). 이것만으로 WCAG 적합성 전체를 보증하는 것은 아니다.
